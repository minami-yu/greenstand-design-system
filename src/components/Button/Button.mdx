# Button

## Overview
Buttons allow users to take actions and move through workflows. They should clearly communicate what will happen when selected and provide a clear visual hierarchy based on the importance of the action.

For Greenstand, buttons should prioritize clarity and ease of understanding, especially for users with varying levels of literacy and digital experience.

## Variants
Choose button variants based on the importance of the action within the current screen.



### Primary
The most important action on the screen. Use for the main task users are expected to complete.
<Canvas of={ButtonStories.Primary} />
<br/>


### Secondary
An alternative action with similar importance to the primary action. 

**Examples**: For the case where there are 2 sign up options, we can assign...
- Primary: Continue with WhatsApp (Default option)
- Secondary: Continue with Email (Alternative option)

<Canvas of={ButtonStories.Secondary} />
<br />



### Tertiary
A lower emphasis action that supports the current task. Use for optional or less important actions.
<Canvas of={ButtonStories.Tertiary} />
<br/>



### Error
A high emphasis destructive action. Use for actions that may cause data loss or irreversible changes.
<Canvas of={ButtonStories.Error} />
<br/>

### Error secondary
A destructive action that should be available but not visually dominant. Use when the action is potentially dangerous but not the primary focus of the screen.

<Canvas of={ButtonStories.ErrorSecondary} />
<br/>

### Accent
Use for actions that need visual distinction from the primary button while remaining important. Use sparingly to highlight specific actions without suggesting higher priority than the primary action.
<Canvas of={ButtonStories.Accent} />


## Icons
Icons can help users quickly understand an action and provide additional context beyond text alone. In Greenstand, icons are encouraged where they improve comprehension, particularly for low literacy users.

<Canvas of={ButtonStories.Icons} />

- **Leading icon**: Use a leading icon to reinforce the button's action.
- **Trailing icon**: Use a trailing icon to indicate progression or navigation. (e.g. Continue, Next step, Open external link)


### Best practices
- Use icons that clearly support the button label.
- Choose familiar and universally recognizable icons.
- Ensure icons add clarity rather than decoration.
- Don't use both leading and trailing icons in the same button.

## Sizes
- **md** (Default): The standard button size used across the product. Recommended for most actions and workflows.

- **sm**: A compact alternative for layouts with limited space.
