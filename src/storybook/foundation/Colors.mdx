# Colors
## Overview
Colors help communicate hierarchy, state, feedback, and brand identity across the product. The color system is built using a layered token architecture that separates color values from their intended usage, making the system easier to maintain, scale, and adapt over time.

## Foundation
The color system consists of two layers: Primitive Colors and Semantic Colors. This approach allows color values to evolve without requiring updates throughout designs and code and enhance the maintainability of the color system.
<br />

- **Primitive Colors**: Primitive colors are the raw color values that form the foundation of the color system (e.g. `color.red-500`). Primitive colors define the available color palette but do not describe how colors should be used.
- **Semantic Colors**: Semantic colors define the purpose of a color within the product (e.g. `color.text.neutral.primary`). Instead of referencing a raw color value or primitive colors, designers and engineers should reference semantic tokens that communicate intent.

## Accessibility
### WCAG AA Compliance
All color combinations used in the product should meet WCAG AA contrast requirements to ensure content remains readable and accessible for a wide range of users.

#### Minimum contrast requirements:
- Normal text: `4.5:1`
- Large text (18px+ or 14px bold+): `3:1`
- Essential UI elements and graphical objects: `3:1`


## Light & Dark Mode
The current design system is optimized for Light Mode. Treetracker is primarily used outdoors in bright environments where higher screen brightness and stronger contrast improve visibility. For this reason, Light Mode is the primary supported experience.

A Dark Mode token set has been defined to support future expansion and theming needs. However, Dark Mode has not yet been fully validated and is not currently considered part of the supported product experience.
