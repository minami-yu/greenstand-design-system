# Iconography

## Overview
Icons help communicate actions, navigation, and status while reducing reliance on text. Icons are especially important in Treetracker because users often have limited literacy or may not be able to read the application's primary language. Clear and recognizable icons help users understand actions and navigation more easily and reduce reliance on text alone.

## Style

### Filled vs outline
The icon system primarily uses **outline icons** with consistent visual weight and stroke appearance. **Filled icons** should be reserved for states that require emphasis, such as selected navigation items or active states.

### Style Consistency
Icons should appear as part of the same family. Choose icons with consistent stroke weights, corner treatments, and visual styles to maintain a cohesive interface.

## Icon library
Treetracker primarily uses Material Design icons for development efficiency and consistency. If a suitable Material Design icon is unavailable, icons from other libraries may be used. When doing so, choose icons that closely match the visual style of the existing icon set.

## Sizes
Use the predefined icon sizes defined in the tokens below. Choose the size that best fits the context while maintaining clarity and visual balance. Icon sizes inside components may be used when necessary to achieve visual balance within a component.

<IconCatalog entries={iconSizes} />

## Colors
Icon colors are defined through color tokens. Refer to the Color documentation for guidance on icon color usage.

## Figma usage
Icons should be added as the component so it can be used for component swap. In Figma, Iconify plugin is useful for searching and adding icons. Use the Material Design icon set (search with prefix: mdi in Iconify) whenever possible to maintain visual consistency across the product.
