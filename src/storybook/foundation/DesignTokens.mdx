# Design tokens

## Definition

- A named design decision (e.g. `color.text.neutral.primary`, `space.400`, `radius.md`)
- Stored as W3C Design Tokens in `tokens/` and compiled to `src/theme/tokens.ts`
- Never hardcode raw hex, px, or font sizes in components when a token exists

## Source layout

- `tokens/variables/` — Figma variable export (Token Studio). Do not hand-edit.
- `tokens/styles/typography.json` — hand-maintained typography styles
- `tokens/styles/elevation.json` — hand-maintained elevation (shadow) styles
- `src/theme/tokens.ts` — generated output. Never edit manually.

## Sync workflow

1. Open Tokens Studio in Figma and remove stale token sets
2. Import variables (leave “Convert numbers to dimensions” unchecked)
3. Export to multiple files and replace `tokens/variables/`
4. Run `npm run build-tokens` and review `src/theme/tokens.ts`

## Styles

- Figma styles are not part of the variable export
- Update `tokens/styles/typography.json` when text styles change
- Update `tokens/styles/elevation.json` when shadow/elevation styles change
- Run `npm run build-tokens` after editing styles JSON

### Elevation schema (`tokens/styles/elevation.json`)

Each level (`sm`, `md`, `lg`) defines three platform targets:

| Key | Purpose |
|---|---|
| `$description` | Guidance copy for docs |
| `figma` | Design reference layers (color, opacity, offset, blur) |
| `ios` | React Native iOS shadow props (`shadowColor`, `shadowOpacity`, …) |
| `android` | Material elevation in dp (plain number, e.g. `2`) |

Optional DTCG wrappers (`"$type"` + `"$value"`) on `figma`, `ios`, or `android` are supported. Color fields may use `{alias}` references like other style tokens.

Compiled output: `theme.elevation.sm.ios`, `theme.elevation.sm.android.elevation`. Use `getShadow(theme.elevation.sm)` in components.

## Build command

Run `npm run build-tokens`.

> Never hand-edit `tokens/variables/` or `src/theme/tokens.ts` — always regenerate through the pipeline.
